我们怎么保护你的数据

不讲术语，先说结论：你的令牌锁在一个只有你有钥匙的柜子里；你的令牌封在一个信封里交给你自己保管，我们这里什么都不存；你查了什么，我们不记；但数据路过我们这里的那一下，技术上是能被看到的。下面一条一条讲清楚。

令牌放在哪：像车站的储物柜

柜子在我们这儿，钥匙只有你有，我们没有留备用钥匙。你每次让 Claude 查 Canvas，Claude 带着你的钥匙来，当场开柜、用完就锁上。

所以就算有人把整份存储或者备份偷走，拿到的也只是一堆打不开的小记录。我们自己去翻，同样只能数出有几条。

令牌放在哪：封进信封，交给你自己拿着

这个部署不保存任何东西。你的令牌被封进一个只有服务器拆得开的信封，这个信封就是你的连接密钥。你每次让 Claude 查 Canvas，Claude 带着信封来，服务器当场拆开、用完就忘。

所以服务器上没有可偷的东西。代价是没法单独作废某一个连接：想作废，就去 Canvas 里把令牌删掉。

数据怎么走：四站路

你问 Claude“这周有什么作业”，这句话会经过四个地方。每一站能看到什么，标在下面。

  1. 你的 Claude

    决定要查什么，带着你的连接密钥发出请求，最后把结果讲给你听。

    看得到 Canvas 内容

  2. 中转平台

    Cloudflare、Vercel 这类中转或托管平台，负责挡攻击、转发请求。加密传输在这里解开，再送往下一站。

    看得到路过的内容

  3. 本站

    用你的钥匙当场解开令牌，去 Canvas 取数据，抹掉邮箱、学号这类字段，再转交回去。

    内容只在内存里路过
    本站保存的 只有加密记录。不存 Canvas 内容，不写日志。
    本站保存的 什么都没有。没有数据库，没有文件，不写日志。

  4. 学校的 Canvas

    数据本来就在这里。它能看到有一台服务器在用你的令牌读数据。

    数据的原主人

中转或托管平台（Cloudflare、Vercel 这类）负责转发请求或运行程序，令牌会从它们手上经过，但它们不保存。

第三行是这套办法的极限：内容要转交给 Claude，就必须在我们的服务器内存里出现一下。我们承诺不去看，也把程序写成了不记录，但这一点你没法验证，只能选择信或不信。

哪些东西根本不会交给 Claude

会转交的

  • 课程、作业和截止时间
  • 成绩和老师的评语
  • 公告、日程、待办
  • 老师的名字

挡在外面的

  • 站内信
  • 同学名单
  • 邮箱、电话、学号、头像
  • 登录和浏览记录
  • 家长账号、个人文件

另外，这个连接只能读。它没有办法替你交作业、改东西或删东西。

你手里的三个开关

  • 给令牌设过期时间。在 Canvas 生成令牌时填上学期结束的日期，到期自动作废。
  • 随时在 Canvas 里删掉令牌。Account → Settings → Approved Integrations，删掉之后这里的连接立刻失效，不需要经过我们。
  • 怀疑密钥泄露就更换。在连接页的“管理连接”里更换密钥或删除连接，旧的就不能用了。
  • 怀疑密钥泄露就重来。先在 Canvas 里删掉令牌，再到连接页用新令牌重新创建连接。
给想看细节的人

每个连接保存为一条固定 288 字节的记录：

标记 4随机数 12密文 256校验 16
  • 连接密钥是 32 字节随机数。服务器不保存它，也不保存它的哈希。
  • 记录名和加密密钥都由“连接密钥 + 服务器随机数”通过 HKDF-SHA256 算出。
  • 内容用 AES-256-GCM 加密，包含学校地址、令牌和注册日期，统一补齐到 256 字节，所以从长度也看不出区别。
  • 不写访问日志和内容日志。
  • 学校地址只接受 instructure.com 的域名；令牌只发往你学校的 Canvas，跳转到别的网站时不会带上。
给想看细节的人
  • 连接密钥 = 12 字节随机数 + AES-256-GCM 密文，密文里是学校地址、令牌和创建日期。
  • 加密密钥由服务器密钥通过 HKDF-SHA256 派生。服务器不保存任何连接密钥，也不保存它们的哈希。
  • 不写访问日志和内容日志。
  • 学校地址只接受 instructure.com 的域名；令牌只发往你学校的 Canvas，跳转到别的网站时不会带上。
  • 更换服务器密钥会让所有已发出的连接密钥一起作废。
